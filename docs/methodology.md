# Methodology

## Research Design

This study uses a **cross-sectional quantitative design**. Data was collected at a single point in time using a structured questionnaire, allowing security perceptions to be measured and compared across gateways and user groups.

## Objectives

1. Measure consumer perceptions of security across Paytm, PayU, and CCAvenue.
2. Assess awareness and adoption of two-factor authentication and encryption.
3. Examine the effect of transaction latency and authentication failures on trust.
4. Identify the security features that most influence trust.
5. Derive risk-mitigation recommendations for financial platforms.

## Population and Sample

| Item | Detail |
|---|---|
| Target population | Digital payment users in India |
| Sampling method | Convenience / voluntary response |
| Sample size | 118 respondents |
| Unit of analysis | Individual respondent |

## Instrument

A structured security questionnaire was designed with the following sections:

1. **Demographics** — age group, occupation, device usage.
2. **Gateway usage** — which gateways respondents use and how often.
3. **Authentication** — awareness and use of 2FA and biometric authentication.
4. **Encryption and privacy** — understanding of encryption and data-handling concerns.
5. **Reliability** — experience with transaction latency and authentication failures.
6. **Trust** — overall confidence in each gateway and in payment infrastructure.
7. **Open feedback** — suggested improvements.

See [`questionnaire.md`](questionnaire.md) for the outline and sample items.

## Variables

| Variable | Type | Measurement |
|---|---|---|
| Gateway used | Categorical | Paytm / PayU / CCAvenue / multiple |
| 2FA awareness | Ordinal | Not aware → Highly aware |
| 2FA adoption | Binary | Uses 2FA / does not |
| Encryption concern | Ordinal | Low → High |
| Transaction latency experience | Ordinal | Never → Very often |
| Authentication failure experience | Ordinal | Never → Very often |
| Privacy concern | Ordinal | Low → High |
| Overall trust | Ordinal | Very low → Very high |

## Data Collection

- Questionnaire distributed digitally to reachable payment users.
- Responses screened for completeness and consistency.
- Incomplete or invalid responses excluded before aggregation.
- Final usable sample: **118 respondents**.

## Analysis Plan (Microsoft Excel)

1. **Data cleaning** — remove duplicates and incomplete records, standardize categories.
2. **Descriptive statistics** — frequencies, percentages, mean/median for ordinal items.
3. **Cross-tabulation** — 2FA adoption vs. trust; privacy concern vs. gateway preference.
4. **Visualization** — bar charts, pie charts, and comparison charts per gateway.
5. **Interpretation** — identify patterns linking security features to trust.

## Ethical Considerations

- Participation was voluntary and informed.
- No personally identifying information is published.
- Responses are reported only in aggregate.
- Raw data is withheld from this public repository.

## Limitations

- Convenience sampling limits generalizability.
- Self-reported data may be affected by perception bias.
- The study captures association, not causation.
- Only three gateways are compared.
